# 全局对象数据

## 概述

`SSS.MKF` 零基 chunk 2 保存全局对象表。对象 ID 是表中的零基记录索引，同时
用于索引 `WORD.DAT` 中的名称。每条记录是一个联合体，同一组字段会按对象 ID
范围被解释为系统文字、角色、物品、法术、敌人或毒，因此解析层不能自行推断类型。

| 版本 | 记录大小 | 字段数 |
|---|---:|---:|
| DOS | 12 字节 | 6 个 `u16` |
| Win95 | 14 字节 | 7 个 `u16` |

当前真实资源是 DOS 布局，共 565 条记录。解析器把两种布局归一化为 7 个字段：
DOS 的原字段 5 是 flags，移动到归一化字段 6，并把新增的字段 5（描述脚本）置零。
Win95 记录则原样保留。

## 物品视图

| 归一化字段 | 含义 |
|---:|---|
| 0 | `BALL.MKF` bitmap 编号 |
| 1 | 价格 |
| 2 | 使用脚本 |
| 3 | 装备脚本 |
| 4 | 投掷脚本 |
| 5 | 描述脚本，DOS 中为 0 |
| 6 | flags |

当前物品运行时使用 `flags` 的 bit 0（可使用）、bit 1（可装备）、bit 2（可投掷）、
bit 3（使用后消耗）、bit 4（作用于全体）和 bit 5（可出售）。物品使用、装备和投掷
脚本会在执行 `0x0001`/`0x0002` 后更新入口，因此运行时和开发快照保存覆盖后的入口，
不能每次都重新读取对象表中的原始字段。`0x0090` 可直接替换任意全局对象的字段
2、3 或 4；版本 20 及后续开发快照额外保存这组联合字段覆盖，以便恢复时撤销快照之后的修改。

这些访问器只应在调用方已知对象是物品时使用。其他对象类型仍可通过无损的原始
字段读取，后续剧情、菜单或战斗实际需要时再增加对应的类型化视图。

## 敌人视图

| 归一化字段 | 含义 |
|---:|---|
| 0 | `DATA.MKF` chunk 1 敌人编号，同时是 `ABC.MKF` sprite 编号 |
| 1 | 法术和毒抗倍率，0 最低、10 最高 |
| 2 | 敌人回合开始脚本 |
| 3 | 战斗结束脚本 |
| 4 | 敌人行动就绪脚本 |

创建战斗实例和召唤敌人时会从 `0x0090` 覆盖后的对象字段复制三个生命周期入口。变身沿用
当前敌人的运行中入口，和原版一样不会用新对象的默认入口覆盖已经推进的生命周期状态。

敌队保存的是这里的全局对象 ID；创建战斗实例时再通过字段 0 取得敌人属性记录。

## 边界要求

- 空 chunk、非对应记录大小整数倍的 chunk 和超过 `u16` ID 空间的表解析失败。
- 调用方必须明确提供 DOS 或 Win95 布局，不能只凭内容猜测联合体版本。
- 对象引用在使用时验证 ID 位于表内；脚本入口和资源编号还需分别验证目标表。
