# 场景地图格式

> 仙剑奇侠传的 2.5D 瓦片地图格式

---

## 概述

仙剑的场景地图使用**等距视角（Isometric / Diamond Shape）**的瓦片（Tile）渲染。地图由两层瓦片组成：底层（地面、墙壁）和顶层（装饰、屋顶、桥梁）。

地图数据存储在 `MAP.MKF` 中，每个 chunk 对应一个场景编号的地图。精灵数据引用 `MGO.MKF` 中的位图。

---

## 场景坐标系

```
           x  →
           * * * * * * * * * *     (y=0, h=0)
            * * * * * * * * * *    (y=0, h=1)
           * * * * * * * * * *     (y=1, h=0)
            * * * * * * * * * *    (y=1, h=1)
           * * * * * * * * * *     (y=2, h=0)
            ....................
  y  ↓
```

### 瓦片形状

- 每个瓦片（Tile）是**菱形（diamond）**，尺寸为 **32×15 像素**
- 使用 (x, y, h) 三元组定位：
  - **x**：水平网格坐标
  - **y**：垂直网格坐标
  - **h**：半层偏移（0 或 1），用于交错排列菱形

### 坐标转换

```
// 地图坐标 → 屏幕像素坐标
PAL_XYH_TO_POS(x, y, h):
    屏幕_x = x * 32 + h * 16
    屏幕_y = y * 16 + h * 8

// 对齐的地图逻辑坐标 → 地图坐标
PAL_POS_TO_XYH(pos, x, y, h):
    h = (屏幕_x % 32 != 0) ? 1 : 0
    x = 屏幕_x / 32
    y = 屏幕_y / 16

碰撞检测也会接收未对齐的像素坐标。此时不能只做整除，而要根据点在
`32×16` 矩形中的位置判断它属于中央菱形还是上、下、左、右相邻菱形；边界规则
与参考实现的 `PAL_CheckObstacle` 一致。
```

## 地图数据结构

```c
struct PALMAP {
    DWORD  Tiles[128][64][2];   // 瓦片数据 [x][y][layer]
    LPSPRITE pTileSprite;       // 瓦片精灵（位图集合）
    INT    iMapNum;             // 地图编号
};
```

### 瓦片数组

- `Tiles[128][64][2]`：128 列 × 64 行 × 2 层（底层、顶层）
- 每个瓦片是一个 **32 位 DWORD**，编码了精灵索引和属性

### DWORD 编码

```
位域分布（32-bit DWORD）：
┌─────────┬─────────┬─────────┬─────────┐
│ 31   24 │ 23   16 │ 15    8 │ 7     0 │
├─────────┼─────────┼─────────┼─────────┤
│ 顶层精灵索引      │ 标志    │ 底层精灵索引    │
└─────────┴─────────┴─────────┴─────────┘
```

**底层精灵索引**（Bottom Layer Sprite Index）：
```
index = (d & 0xFF) | ((d >> 4) & 0x100)
```
这表示底层索引由低 8 位和第 12 位组合（实际上是一个 9 位值）。

**顶层精灵索引**（Top Layer Sprite Index）：
```
d >>= 16;
index = ((d & 0xFF) | ((d >> 4) & 0x100)) - 1
```
高 16 位右移后同样编码。（减 1 是因为 0 表示"无顶层"）

**阻挡标志**（Block Flag）：
```
blocked = (d & 0x2000) != 0
```
玩家/角色不能通过标记了阻挡的瓦片。

## 渲染方式

### 两层渲染

场景先把两层地图绘制为底图：

1. **底层（Layer 0）**：地面、道路、墙壁等
2. **顶层（Layer 1）**：屋顶、树冠、桥梁等

随后将角色/事件精灵与 `tile_height > 0` 的覆盖瓦片放入同一绘制队列，按逻辑
纵坐标排序后重绘。覆盖瓦片可能来自底层或顶层；不能简单固定为“底层 → 角色 →
顶层”，否则墙体、门洞和桥梁附近会出现角色视觉位置与碰撞位置不一致。

### 从后到前绘制

为获得正确的遮挡效果，地图瓦片按 **从远到近（y 从小到大）** 的顺序绘制。同 y 的行内，x 从小到大或从大到小均可，因为菱形瓦片不重叠。

### 场景结构

```c
struct SCENE {
    WORD wMapNum;             // 地图编号
    WORD wScriptOnEnter;      // 进入场景时触发的脚本
    WORD wScriptOnTeleport;   // 传送出场景时触发的脚本
    WORD wEventObjectIndex;   // 事件对象起始编号
};
```

场景表（`rgScene[MAX_SCENES]`）存储了游戏中所有场景的定义。

## 在 Rust 中的数据结构

```rust
/// 瓦片数据
struct Tile {
    /// 底层精灵在 MGO.MKF 中的索引
    bottom_sprite: u16,
    /// 顶层精灵索引（None 表示无顶层）
    top_sprite: Option<u16>,
    /// 是否阻挡通行
    blocked: bool,
}

/// 场景地图
struct Map {
    /// 地图编号
    num: i32,
    /// 瓦片网格 [x][y][layer]
    tiles: Vec<Vec<[Tile; 2]>>,
    /// 瓦片精灵位图集合
    tile_sprites: Vec<RleBitmap>,
}

/// 场景定义
struct Scene {
    map_num: u16,
    script_on_enter: u16,
    script_on_teleport: u16,
    event_object_index: u16,
}
```
