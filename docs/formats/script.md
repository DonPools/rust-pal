# 脚本记录格式

## 存储

`SSS.MKF` chunk 4 是连续的脚本记录表。每条记录固定为 8 字节：

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `u16` | opcode |
| 2 | `u16` | operand 0 |
| 4 | `u16` | operand 1 |
| 6 | `u16` | operand 2 |

所有字段均为 little-endian。场景和事件对象保存的脚本入口直接作为记录表索引，记录
0 通常作为空入口。解析器要求 chunk 非空且长度是 8 的整数倍；执行时仍需验证每个
入口和跳转目标没有越界。

## 运行时模块边界

脚本记录仍只有一份 `ScriptOpcode` 目录和一套底层记录解码器，但原版需要保留三种
不同的调度语义：

- `pal-core/src/script/trigger/` 执行触发、进入场景、战斗、物品和仙术脚本，按消息、
  等待、表现或动作产出 `ScriptEvent`。
- `pal-core/src/game/script_actions.rs` 将 `ScriptAction` 应用到 `GameState`；它是游戏
  状态落地层，不重新解释 raw opcode。
- `pal-core/src/game/auto_script.rs` 为当前场景的每个事件对象推进 `auto_script`，每次
  固定更新最多执行一条对象指令；自动脚本的 idle 计数、追逐和错误保留规则属于该调度器。
- `pal-core/src/game/equipment_scripts.rs` 在战斗开始前同步重放装备脚本，并在失败时回滚
  角色、装备效果和脚本入口。

三种模式共享 `pal-core/src/script/executor.rs` 中的记录解码、对象选择哨兵、程序计数器
和调用帧表示，但不共享暂停、等待、入口持久化或错误处理语义。这样可以减少相同 opcode
的解析重复，同时保留触发脚本与自动脚本之间原本不同的调度行为。

`pal-core::script::inspect_script_records` 为开发工具提供只读、定长的脚本表窗口，并标注
停止、跳转、调用、条件分支和随机选择。`ScriptReferenceCatalog` 进一步索引场景
enter/teleport、事件对象 trigger/auto 和指令级 jump/call 的入站引用，并保留全局事件对象
ID 到场景的映射。工具不会把入口之后遇到的第一个 `STOP` 当作可靠的脚本边界，因为原始
记录可以共享尾部、跳入任意入口或形成循环。独立场景检查器据此提供目标跳转、历史导航、
引用与对象反向定位，并从 `M.MSG` 只读预览 `PrintMessage` 文本，但不会执行或修改脚本。

## 当前运行时覆盖

触发脚本运行时目前实现以下 opcode：

代码中的权威指令目录是 `pal-core::script::ScriptOpcode`。它为原版 165 个有效 opcode
提供稳定的 Rust 变体名、中文行为注释和触发脚本 handler 分类。原版编号空间中的
`0x0032`、`0x0048`、`0x0072` 和 `0x009D` 是空洞，不属于指令集。

| Opcode | 行为 |
|---:|---|
| `0x0000` | 结束脚本 |
| `0x0001` | 结束并将事件对象入口更新为下一条记录 |
| `0x0002` | 结束并将入口改为 operand 0；operand 1 可限制重复次数 |
| `0x0003` | 无条件跳转到 operand 0 |
| `0x0004` | 调用 operand 0 指定的子脚本，operand 1 可选择事件对象 |
| `0x0005` | 请求重绘并延时 operand 1 个 60ms 周期，0 按 1 周期处理 |
| `0x0006` | 按 operand 0 指定概率跳转到 operand 1；运行时使用确定性随机序列 |
| `0x0007` | 创建战斗请求并暂停场景脚本；胜利继续，失败/逃跑跳到对应 operand |
| `0x0008` | 将事件对象入口更新为下一条记录并继续 |
| `0x0009` | 等待 operand 0 帧，0 按 1 帧处理；每帧继续推进场景自动脚本 |
| `0x000A` | 显示“否/是”确认菜单；选择否时跳转到 operand 0 |
| `0x000B..0x000E` | 当前事件对象以速度 2 向指定方向走一步 |
| `0x000F` | 设置当前事件对象方向和/或帧 |
| `0x0010` | 当前事件对象以速度 3 走到指定 tile |
| `0x0011` | 当前事件对象以速度 2 隔帧走到指定 tile |
| `0x0012` | 相对玩家位置设置事件对象位置 |
| `0x0013` | 设置事件对象绝对位置 |
| `0x0014` | 设置当前事件对象动作帧并面向南 |
| `0x0015` | 设置队伍槽位方向和动作帧；槽位尚未加入角色时也保留 |
| `0x0016` | 设置指定事件对象方向和动作帧 |
| `0x001B` | 增减当前角色或全队 HP；死亡或数值未变化时失败 |
| `0x001C` | 增减当前角色或全队 MP；死亡或数值未变化时失败 |
| `0x001D` | 以同一数值增减当前角色或全队 HP、MP |
| `0x001E` | 增减金钱；余额不足时跳转到 operand 1 |
| `0x0020` | 移除物品，必要时卸下当前队员装备；不足时跳转到 operand 2 |
| `0x0022` | 以最大 HP 的十分比复活当前角色或全队死亡角色 |
| `0x0024` | 设置 operand 0 指定事件对象的自动脚本入口 |
| `0x0025` | 设置 operand 0 指定事件对象的触发脚本入口 |
| `0x0026` | 打开 operand 0 指定的买入商店 |
| `0x0027` | 打开当前背包的卖出菜单 |
| `0x0030` | 将基础角色属性的 operand 1 百分比写入当前战斗临时效果；operand 2 可指定角色 |
| `0x0031` | 临时把当前角色的战斗 sprite 替换为 operand 0；0 恢复开战值 |
| `0x0033` | 累加当前敌人的炼化值；敌人不可炼化时跳转 operand 0 |
| `0x0034` | 随机消耗炼化值并从商店 0 的对应槽生成一件物品 |
| `0x0038` | 执行当前场景传送脚本；没有传送脚本时将脚本标记为失败并跳转到 operand 0 |
| `0x003B` | 后续消息居中；operand 0 为 palette 字色 |
| `0x003C` | 后续消息在上方；operand 0 为头像，operand 1 为 palette 字色 |
| `0x003D` | 后续消息在下方；operand 0 为头像，operand 1 为 palette 字色 |
| `0x003E` | 后续消息使用居中窗口；operand 0 为 palette 字色 |
| `0x003F` | 队伍乘坐当前事件对象，以速度 2 移动到指定 tile |
| `0x0040` | 设置 operand 0 指定事件对象的触发方式 |
| `0x0041` | 将当前脚本标记为失败；场景中的消耗型物品因此不会扣除 |
| `0x0042` | 在战斗中模拟 operand 0 法术；operand 1 为施法强度，operand 2 可指定一基敌人槽 |
| `0x0044` | 队伍乘坐当前事件对象，以速度 4 移动到指定 tile |
| `0x0047` | 播放 operand 0 指定的 `VOC.MKF` 音效 |
| `0x0043` | 播放或停止场景 RIX 音乐，并设置循环和淡入参数 |
| `0x0045` | 设置下一场战斗的音乐编号 |
| `0x004A` | 设置下一场战斗的 `FBP.MKF` 战场编号 |
| `0x0049` | 设置事件对象状态 |
| `0x004B` | 将当前事件对象暂时隐藏 15 帧 |
| `0x004C` | 让当前事件对象在指定范围和速度下追逐玩家 |
| `0x0046` | 将所有固定队伍槽位放到 operand 0/1/2 指定的地图 tile 并按当前方向排开 |
| `0x0050..0x0051` | 淡出并标记下一次场景绘制自动淡入，或显式淡入画面 |
| `0x0059` | 逻辑上选择目标场景；当前触发脚本结束后才加载并替换地图和事件对象 |
| `0x0057` | 以当前角色扣除施法消耗后的 MP 乘以倍率改写当前法术伤害并清空 MP；倍率 0 按 8 |
| `0x0058` | 物品数量少于 operand 1 时跳转到 operand 2 |
| `0x005C` | 让玩家队伍隐藏 operand 0 个完整战斗回合，期间敌人不能行动 |
| `0x0062` | 将全局敌人追逐范围设为 0，并在 operand 0 个更新周期后恢复为 1 |
| `0x0063` | 将全局敌人追逐范围设为 3，并在 operand 0 个更新周期后恢复为 1 |
| `0x0066` | 在投掷物品脚本中按角色攻击力计算强度，并模拟 operand 0 法术攻击当前敌人目标 |
| `0x006A` | 按 operand 0 成功率从当前敌人偷取物品或金钱；0 表示必定成功 |
| `0x0068` | 敌方法术或攻击等效物品脚本执行期间跳转到 operand 0；ready 脚本不算敌方回合 |
| `0x006B` | 将 operand 0 按有符号 word 解释为当前法术的吹飞范围，逐帧随机累加到受击一方的位置 |
| `0x006C` | 按偏移移动事件对象并推进动画 |
| `0x006D` | 修改指定场景的进入脚本和传送脚本入口 |
| `0x006E` | 按偏移移动玩家、推进队伍步行动画并更新相机 |
| `0x006F` | 指定对象状态匹配时同步当前事件对象状态 |
| `0x0065` | 设置 operand 0 角色的场景精灵；operand 2 非零时立即重载当前非战斗队伍精灵 |
| `0x0070` | 队伍以速度 2 逐帧走到指定 tile |
| `0x0073` | 从备份画面淡变到当前场景；operand 0 越大越慢，当前识别后继续 |
| `0x0074` | 任一队员 HP 未满时跳转到 operand 0 |
| `0x0075` | 用三个 operand 设置队伍成员并切换队长场景精灵 |
| `0x0078` | 原版保留的空操作，识别后继续执行 |
| `0x007F` | 直接定位、逐帧滚动或恢复玩家跟随 viewport |
| `0x0081` | 玩家未面向指定当前场景对象时跳转到 operand 2 |
| `0x0083` | operand 0 对象不在当前脚本对象的 operand 1 范围内时标记失败并跳转 operand 2 |
| `0x0084` | 将 operand 0 对象放到玩家面前并设为 operand 1 状态；受阻时跳转到 operand 2 |
| `0x0085` | 延时 operand 0 个 80ms 周期 |
| `0x0086` | 队伍装备的 operand 0 物品少于 operand 1 时跳转到 operand 2 |
| `0x0087` | 推进当前事件对象动画一帧 |
| `0x0088` | 最多消耗 5000 金钱，以消耗额的五分之二改写当前法术伤害 |
| `0x008A` | 启用下一场战斗的自动选招，并在该场结算后清除 |
| `0x008D` | 将当前角色提升 operand 0 级并按原版随机成长属性；不恢复 HP/MP |
| `0x008E` | 恢复画面；当前同步渲染管线中继续执行 |
| `0x008F` | 将当前金钱向下折半 |
| `0x0090` | 将 operand 0 全局对象的第 `2 + operand 2` 个联合字段改为 operand 1；operand 2 只接受 `0..=2` |
| `0x0092` | 在战斗中播放 operand 0 一基队员的预施法动作（0 跳过），再对全队播放五步色移 |
| `0x0094` | 当前或指定事件对象状态等于 operand 1 时跳转到 operand 2 |
| `0x0095` | 当前场景等于 operand 0 时跳转到 operand 1 |
| `0x0096` | 播放 400 帧 DOS 结局动画；拼接 FBP 61/62，并叠加 MGO 571/572 |
| `0x0097` | 队伍乘坐当前事件对象，以速度 8 移动到指定 tile |
| `0x009A` | 将 operand 0..=1 的事件对象状态批量设为 operand 2 |
| `0x00A1` | 将队员位置和队伍 trail 收拢到队长位置 |
| `0x00A2` | 在后续 operand 0 条指令中随机选择一条执行 |
| `0x00A3` | 请求 CD 音轨；当前无 CD 后端时循环播放 operand 1 的资源音乐 fallback |
| `0xFFFF` | 将 operand 0 指向的 `M.MSG` 消息追加到当前对话页 |

执行器每次推进最多处理 1024 条非消息指令，以防损坏数据或跳转环导致主循环失去
响应。未实现的 opcode 会返回包含脚本入口和 opcode 的错误，不会静默跳过。

场景事件对象的自动脚本按固定更新每个对象执行一条指令，无条件跳转除外。当前自动
脚本支持停止/入口替换、`0x0002`/`0x0003` 跳转、等待、`0x000F`/`0x0014`/`0x0016`
当前或指定对象姿态、`0x0010` 走到
指定 tile、`0x007C`/`0x0082` 对象移动、`0x007D` 对象偏移、`0x007E` 层级修改、
`0x0083` 对象范围分支、对象状态和消息跳过。这与触发脚本是两种调度方式；场景 1
开场后 NPC 走到门口并启用出口依赖 `0x0010` 自动脚本。单个对象的自动脚本出错时，
其他对象在同一更新内已经产生的画面变化仍会保留并触发重绘。

`0x0075` 的非零 operand 是一基角色编号，按 operand 顺序组成新队伍；`0` 表示空槽。
三个 operand 全为 `0` 时按原版兼容行为回退为角色 0。运行时会先验证角色编号和重复
成员，非法输入不会部分修改现有队伍。该指令只替换槽位中的角色并重载精灵，不会收拢
队形；此前由 `0x0046` 和 `0x0015` 写入未激活槽位的位置、方向和动作帧必须保留。
队员场景角色使用五点 trail 跟随队长，普通
行走、脚本行走、骑乘和坐标偏移都会同步更新；`0x00A1` 会重置该 trail。

`0x007F` 的 operand 0/1 都为 0 时恢复玩家跟随。operand 2 为 `0xFFFF` 时，viewport
直接设为 `(operand0 * 32 - 160, operand1 * 16 - 112)`；其他值将 operand 0/1 作为
有符号像素偏移逐帧执行，并在每帧推进场景自动脚本。脚本锁定状态和 viewport 坐标
包含在开发快照中。

物品数量条件与 `0x0020` 按原版统计背包和当前队员装备。`0x0020` 的 operand 1 为
0 时按 1 处理；operand 2 非零时，数量不足会保持背包和装备不变并跳转。operand 2
为 0 时允许部分移除，顺序是背包优先，再按队伍顺序和装备栏顺序卸下匹配物品。
`0x0026`/`0x0027` 的商店布局与交易规则见 `store.md`。

`0x0043` 的 operand 0 是音乐编号。operand 1 不等于 `1` 时循环播放；值为 `3` 且
音乐不是 9 时请求三秒淡入。核心状态会记录当前音乐编号，桌面端按系统菜单或启动参数
选定的 RIX/OPL2 或 MIDI/SoundFont 后端播放；曲目失败时不会静默切换音色。
`0x0047` 的 operand 0 直接对应 `VOC.MKF` 的零基 chunk。

`0x0050` 与原版 `fNeedToFadeIn` 一致：淡出结束后先允许脚本继续；如果后续没有显式
`0x0051`，则在脚本结束、对话或菜单等下一次可见场景绘制前，用速度 1 自动淡入并清除
此前的全屏图片覆盖。若淡出后紧接 `0x0037`，RNG 播放器会在绘制第一帧后执行同样的
自动淡入，再继续剩余动画；例如酒剑仙授艺使用的 RNG 1 包含 411 帧。`0x0059` 只立即
更新逻辑场景编号并登记资源切换，地图和事件对象要到
当前触发脚本结束、返回帧循环后才替换。因此场景 1 出口脚本 4475 会保持旧 framebuffer
完成淡出，再加载场景 3、执行其进入脚本并自动淡入，不会先显示一帧新场景。

传送 opcode 会将场景传送入口作为嵌套脚本调用执行。子脚本结束后返回原脚本的下一条
记录；不存在入口或调用失败时才跳转其失败入口。嵌套调用共享原脚本的成功状态和调用
深度，开发 inspector 仍能显示当前子脚本指令。

`0x0058`、`0x0094` 和 `0x0095` 会产生独立的条件事件，由持有物品、场景和事件对象
状态的世界层决定是否跳转。`0x009A` 使用全局一基事件对象 ID；当前要求整个 ID 区间
都存在于全局事件对象表，否则拒绝操作，避免只修改区间中的一部分。未进入场景的对象
也可由状态、触发脚本和自动脚本相关 opcode 修改，进入场景后会沿用该全局状态。

场景物品使用脚本以目标角色 ID 作为脚本 owner；作用全体时 owner 为 `0xFFFF`。每次执行
初始为成功状态，HP/MP/复活效果会按实际属性是否变化更新成功状态。脚本完成后总是保存
新的使用入口，但只有物品带 consuming flag 且脚本成功时才从背包扣除一个。

`0x0052` 会将当前事件对象状态取反并设置临时消失计时，operand 0 为 0 时使用原版默认
值 800；计时归零后，对象在离开视口时恢复正状态并重置动画。`0x0079` 按角色属性中的
名称 word ID 检查队伍成员，而不是比较角色编号。
`0x007A`、`0x007B` 分别以 4、8 的速度移动队伍；`0x007C`、`0x0082` 移动当前
事件对象。原版 `0x007C` 隔帧移动 4 像素，固定 50ms tick 下等效为每帧 2 像素。
`0x007D` 只偏移对象坐标、不推进动画，`0x007E` 设置对象绘制层级。

`0x003F`、`0x0044`、`0x0097` 的骑乘移动会让队伍和当前事件对象整体平移，但保持
双方当前姿态，不推进队员步态或事件对象动画；这与 `0x006E` 的步行偏移不同。

`0x0007` 产生战斗请求后保留当前执行位置并暂停脚本。桌面战斗完成且玩家确认结算后，
胜利从下一条记录继续，失败和逃跑分别使用 operand 1/2 的非零入口。operand 2 为 0
时该战斗不可逃跑。`0x0045` 和 `0x004A` 设置后续战斗的音乐和战场背景，并随开发快照
保存。
