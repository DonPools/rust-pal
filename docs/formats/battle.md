# 战斗数据格式

## DATA.MKF 战斗表

当前 DOS 资源的战斗静态数据分布如下。所有数值均为 little-endian；带符号字段使用
`i16`，其余为 `u16`。

| Chunk | 记录大小 | 当前记录数 | 内容 |
|---:|---:|---:|---|
| 1 | 70 字节 | 154 | 敌人属性和动画参数 |
| 2 | 10 字节 | 380 | 每队最多五个敌人对象 ID |
| 5 | 12 字节 | 65 | 战场波动和五系法术修正 |
| 6 | 20 字节 | 20 | 五名可入队角色的升级习得法术 |
| 10 | 可变 | 1 | 通用物理命中和玩家预施法 GOP sprite |
| 11 | 40 字节 | 1 | `10 x 2` 个玩家战斗 sprite 特效组索引 |
| 13 | 100 字节 | 1 | 按敌人数和槽位组织的战斗站位 |
| 14 | 200 字节 | 1 | 0..99 级升级经验阈值 |

### 敌人记录

敌人记录包含 35 个 word：

| Word | 字段 |
|---:|---|
| 0..4 | 待机帧、法术帧、攻击帧、待机速度、动作等待帧 |
| 5 | Y 坐标偏移 |
| 6..10 | 攻击、动作、法术、死亡和登场音效，按 `i16` 读取 |
| 11..16 | HP、经验、金钱、等级、法术编号和施法概率 |
| 17..20 | 攻击等效物品及概率、偷窃物品及数量 |
| 21..26 | 攻击、灵力、防御、身法、逃跑和毒抗 |
| 27..31 | 五系抗性 |
| 32..34 | 物理抗性、双行动标记和炼化价值 |

敌队中的值是 `SSS.MKF` 全局对象 ID，不是 chunk 1 的直接索引。敌人对象的字段 0
才是 chunk 1 敌人编号，同时也是 `ABC.MKF` 的敌人 sprite 编号。值 `0xFFFF` 表示
队伍布局结束；值 `0` 是空槽。使用时必须依次验证敌队、全局对象和敌人定义索引。

### 敌人站位

chunk 13 是 `5 x 5` 个 `(x, y)` 坐标。第一维是敌人槽位，第二维是布局槽数减一。
尾部 `0xFFFF` 不计入布局槽数，值为 0 的空槽仍保留其位置。

### 攻击法术记录

`DATA.MKF` chunk 4 的法术记录固定为 16 个 word。带符号的位移、层级和速度字段按
`i16` 读取：

| Word | 字段 |
|---:|---|
| 0 | `FIRE.MKF` 效果 sprite 编号；召唤类改作效果法术编号 |
| 1 | 法术类型：0 单体、1 分散全体、2 整体、3 战场、4 单人辅助、5 全队辅助、8 变身、9 召唤 |
| 2..3 | 效果 X/Y 坐标偏移，按 `i16` 读取 |
| 4 | 普通法术的绘制层偏移；召唤类的召唤 sprite 编号，按 `i16` 读取 |
| 5 | 每帧速度修正，按 `i16` 读取；原版帧间隔为 `(speed + 5) * 10ms` |
| 6 | 是否把最后一帧保留到战场背景（`0xFFFF` 表示保留） |
| 7 | 起火帧；循环播放从该帧重新开始 |
| 8 | 效果附加循环次数 |
| 9 | 末尾震屏帧数 |
| 10 | 战场横向波动增量 |
| 11 | 保留字段 |
| 12 | MP 消耗 |
| 13 | 基础伤害 |
| 14 | 五系编号；0 表示无属性 |
| 15 | 音效编号，按 `i16` 读取 |

MP 消耗从 byte 24 开始，不能与 byte 26 的基础伤害互换。对象表中的法术对象先通过
字段 0 取得这里的法术编号。

## 图像资源

- `ABC.MKF`：敌人 GOP sprite；编号来自敌人对象字段 0。
- `F.MKF`：玩家战斗 GOP sprite；编号来自 `PLAYERROLES.rgwSpriteNumInBattle`。
- `FIRE.MKF`：法术效果 GOP sprite；普通法术使用 chunk 4 word 0，召唤本体使用
  `F.MKF` 的 `word 4 + 10`。
- `DATA.MKF` chunk 10/11：chunk 10 是所有战斗员共用的 GOP；chunk 11 每行对应一个
  玩家战斗 sprite，第一列选择十帧预施法组（`group * 10 + 15`），第二列选择三帧
  武器命中组（`group * 3`）。敌人物理命中固定使用通用帧 9..11。
- `FBP.MKF`：`320 x 200` 战场背景；编号由脚本 `0x004A` 设置。

这些资源可能直接保存 GOP/RLE，也可能经过 YJ_1 压缩；解码时保留 MKF 原始编号，
空 chunk 或格式错误不能改变后续索引。

### 原版战斗 HUD 与选择状态

Classic 战斗 HUD 复用 `DATA.MKF` chunk 9 的 UI sprite。玩家信息框使用 sprite 18，
按 `(91 + 77 * party_index, 165)` 排列；头像使用 `48 + role_id`，斜线使用 sprite 39，
黄色和青色数字分别从 sprite 19、56 开始。当前行动角色头顶交替显示 sprite 68、69。

主指令采用原版十字布局，而不是同时移动目标与切换指令：攻击、仙术、合体和其他分别
使用 sprite 40..43，坐标依次为 `(27,140)`、`(0,155)`、`(54,155)`、`(27,170)`。
方向键在主指令状态选择图标，确认普通攻击或单体攻击仙术后才进入敌人选择；选敌时以
palette 索引低四位增加 7 的闪烁效果标记当前目标，取消则返回主指令状态。仅剩一个敌人
或行动作用于全体时省略选敌步骤。桌面层必须单独记录这两个状态，因为核心层提交玩家
指令时可以成功返回空事件；是否已有表现事件不能用于判断指令是否提交成功。

战斗菜单保持独立状态：主十字、仙术列表、其他、物品子菜单、敌方目标、我方目标和状态页。
Esc 在主十字撤销上一名队员已提交的指令并释放物品预留；在子菜单中只返回上一级，不会
直接逃跑。快捷键沿用原版语义：`R` 全队重复上一回合，`A` 切换持续普通攻击，`D` 防御，
`E` 使用物品，`W` 投掷物品，`Q` 全队逃跑，`S` 状态，`F` 为本回合全队强制攻击法术。
仙术会按对象 flags 进入敌方/我方的单体或全体目标；合体技要求当前角色和至少另一名队员
健康，单体合体技进入选敌，全体合体技直接提交。其他菜单依次为自动、物品、防御、逃跑、
状态，物品子菜单再区分使用与投掷。

仙术列表使用 `(10,42)` 的 style 1 UI 九宫格和顶部现金/MP 单行框；三列间距为 87 像素，
每页可见五行，并以前后两行为中心滚动而不是按 15 项硬分页。封咒时仙术指令和列表项都直接
显示为不可用，合体技条件不满足时也不能把主指令光标移到对应图标。Classic 单体辅助仙术和
单体使用物品从队员 0 开始选目标，单人队伍省略目标选择。其他与物品子菜单分别使用
`(2,20)`、`(30,50)` 的原版 UI 框。战斗中的状态入口复用完整 FBP 0 状态页，并以战斗实例
覆盖 HP、MP 和临时属性，同时显示经验、装备及当前毒。

## 脚本入口与首战基线

`0x0007` 的三个 operand 分别为敌队编号、失败跳转和逃跑跳转。operand 2 为 0 时按
不可逃跑的首领战处理。执行器在战斗期间暂停调用方脚本，胜利继续下一条，失败或逃跑
在对应入口非零时跳转。

当前真实资源中，场景 1 的事件对象 28 从 entry 6906 启动战前过场，随后自然执行到
entry 6965 的首场剧情战斗：

```text
6963  SET_PARTY    1, 2, 0
6964  BATTLEFIELD  21
6965  BATTLE       18, 40091, 0
6966  MUSIC        24, 3, 0
```

敌队 18 是两个对象 495（“苗人拳”），胜利后继续 entry 6966，失败跳到 40091，
不能逃跑。

开战前按六名角色和六个装备栏重放装备脚本，以重建攻击、防御、战斗精灵和音效等
派生字段。部分初始饰品还设置临时战斗状态；这些状态和角色身上的毒会在创建战斗时复制
到战斗实例，并在结算时写回长期游戏状态。开发快照保存六名角色的状态、每人 16 个毒槽
和炼化累计值；读取 DOS/Win95 原版存档时，毒槽按存档中的队伍位置映射回角色。

### 状态与毒

DOS/Classic 的状态编号为 0..8，依次是混乱、麻痹、昏睡、封咒、傀儡、勇敢、保护、
加速和双击。负面状态已存在时不延长；傀儡只对死亡角色生效；正面状态保留较长持续
时间。装备脚本使用大于 999 的持续时间，普通移除指令不能清除。每个完整回合结束后，
玩家和敌人的状态持续时间各减一。

当前战斗规则已接入昏睡/麻痹跳过行动、封咒禁止施法、傀儡维持死亡角色战斗资格、
勇敢物理暴击、保护减伤、双击和敌人双行动。玩家先完成本回合指令选择，随后敌我行动
按实际敏捷乘以连续的 `RandomFloat(0.9, 1.1)` 后截断并降序执行；DOS/Classic 的加速状态
会把玩家敏捷乘以 3，上限为 999，濒死状态再减半。死亡、昏睡和麻痹角色仍以身法 0、
普通攻击进入行动队列；如果在轮到自己前恢复，就能在同一回合行动。死亡傀儡不进入手动指令选择，
但会使用这条身法 0 的普通攻击。混乱玩家不进入指令选择，若未濒死则随机攻击一名
存活队友；混乱敌人会随机选择一名存活敌人攻击，若选中自己则放弃本次行动。

普通单体攻击有 `1/6` 概率暴击，勇敢状态必定暴击；李逍遥另有独立的 `1/12` 额外一击，
两个倍率可以叠加，最后再乘以 `RandomFloat(1, 1.125)` 并截断。全体物理攻击按敌方槽位
`2,1,0,4,3` 处理，第一目标为完整伤害，之后
每个有效目标继续减半。敌人物理攻击每次有 `7/17` 概率自动防御；濒死或混乱、昏睡、麻痹
角色在判定成功时先查 `covered_by` 对应的健康队员进行援护。援护或自动防御会完全挡住
物理伤害，也不会触发攻击等效物品。敌方法术对无上述负面状态的目标另有 `1/3` 自动防御
概率，并按“防御倍率 × 保护倍率 + 自动防御”作为伤害除数。

Classic 合体技收集全部健康队员，把各自攻击和灵力之和除以 4 作为法术强度；每名贡献者
扣除等同法术 MP 消耗的 HP，但至少保留 1 HP。同回合合体技以十倍身法优先执行，完成后
跳过其他队员动作。防御为五倍身法，辅助法术和使用物品为三倍，逃跑为一半身法。

玩家和敌人各有 16 个毒槽，每槽保存毒对象 ID 与下一次脚本入口。毒对象复用全局对象
记录：word 0 是毒等级，word 1 是显示颜色，word 2 是玩家脚本，word 4 是敌人脚本。
添加时拒绝对象 0、避免重复并遵守玩家毒抗或敌人法术抗性；解毒可按对象或毒等级执行。
新毒添加后立即排入其首次脚本。完整回合结束时先清除手动防御，再按队伍顺序逐个执行
“该玩家全部毒脚本 -> 该玩家状态递减”，随后按敌人顺序逐个执行同样流程；不能把全部
毒脚本和全部状态递减拆成两个批次。脚本可以跨帧暂停于对话、延时和视觉事件，完成后
返回的 `next_entry` 会写回对应毒槽，供下一回合继续。离开战斗时按原版清除持续时间
不超过 999 的临时状态和等级不超过 3 的毒；装备脚本状态与更高等级毒继续保留。

### 行动后检查

`PAL_BattlePostActionCheck` 不只是胜负判断。每次检查会把本次真正倒下的敌人计入经验和
金钱；脚本强制胜利时，仍存活的敌人不能获得奖励。敌方行动还会比较行动前后的玩家 HP：

- 队员刚死亡时，按其 `covered_by` 找到可响应的队员，并执行响应者姓名对象上的
  `wScriptOnFriendDeath`。
- 玩家首次从健康区掉入濒死区时播放 `dying_sound`，并执行该玩家姓名对象上的
  `wScriptOnDying`；响应者必须仍在队伍中且没有昏睡、麻痹或混乱。
- 两种脚本每次行动最多触发一条，返回入口写回全局对象，之后的存档和战斗继续使用该入口。
- 自动战斗跳过死亡与濒死脚本，保持原版行为。

玩家动作在实际执行前还会重新验证。攻击/辅助法术失效分别回退为普通攻击/防御；投掷物品
数量变为 0 时回退普通攻击，使用物品数量变为 0 时回退防御，失效的单体敌方目标自动改选。
Repeat 只在非重复回合进入行动队列前更新上一动作缓存，因此重复动作本回合发生的缺 MP、
缺物品回退不会污染下一次 Repeat。持续自动攻击在行动执行阶段向队列中的后续健康玩家传播，
不会重新计算这些玩家已经排定的身法；Repeat 会恢复上一回合的持续自动攻击开关。

敌人的生命周期脚本也使用同一调度器：开战先按敌人顺序执行 turn-start；每次敌人行动
前执行 ready（双行动会执行两次）；回合毒与状态处理后再次执行 turn-start；胜利后、
结算前执行 battle-end。turn-start 和 battle-end 都按原版固定槽位逐条读取，前一个脚本
完成后才检查下一槽当前的敌人及入口。敌人按记录中的概率施放法术，封咒会强制改为普通攻击；
法术的 use 和 success 脚本以目标角色 ID 执行并分别写回下一入口。use 脚本失败时跳过 success
脚本，但原版的基础伤害仍会结算。非单体类型攻击全部存活玩家，五系、毒抗、战场修正
和保护状态参与减伤。普通攻击后，攻击等效物品先按记录中的十分比概率判定，再要求
`1..=100` 的随机值大于目标毒抗；命中后以目标角色 ID 执行物品 use 脚本，并将返回的
下一入口写回对应物品对象。ready 脚本执行时不视为敌方行动，法术和攻击等效物品脚本
执行期间才满足 `0x0068` 的敌方回合条件。脚本造成的 HP、状态和毒变化以活动战斗实例
为准，并同步回角色长期状态。原版结果 `0` 作为独立的“脚本终止”结果处理：不发奖励，
也不走失败/逃跑跳转，但会让调用方剧情继续。

玩家攻击法术在敏捷队列轮到施法者时扣除 MP，再按“use 脚本 -> success 脚本 -> 伤害”
执行。use 失败会跳过动画、success 和伤害；success 的成功状态不阻止原版基础伤害。
`0x0057` 会用扣除施法消耗后的剩余 MP 乘以指定倍率（0 按 8）改写当前法术伤害并清空
MP；`0x0088` 最多消耗 5000 金钱，并按 `cash * 2 / 5` 改写当前法术伤害。两个脚本入口
分别返回后，法术的 use/success 入口都会持久化各自的下一入口。`0x0042` 使用 operand 1
作为模拟施法强度，并叠加法术定义中的基础伤害；单体目标失效时自动改选存活敌人，全体
法术遍历全部存活敌人。

玩家战斗物品分为使用和投掷两套列表。提交指令时，消耗型使用物品与所有投掷物品会
按物品 ID 预留库存，避免同一回合多名角色重复选择最后一个物品；真正轮到角色且物品
脚本完成后才扣除。角色在行动前死亡或失能时不消耗。使用脚本以目标角色 ID 为 owner，
作用全体时为 `0xFFFF`；消耗型使用物品不受脚本成功标记影响，执行后总是扣除一个，
非消耗型不扣。投掷脚本以敌人槽位为 owner，作用全体时为 `0xFFFF`，执行后总是扣除。
两种脚本返回的下一入口分别持久化，开发快照版本 18 保存投掷入口覆盖。

`0x0066` 只在投掷物品脚本内生效。它以 operand 0 选择模拟法术，强度为
`operand1 * 5 + acting_player.attack_strength * random(0..=3)`，目标沿用当前投掷脚本
owner，并复用模拟玩家法术的全体目标、抗性、战场修正和伤害反馈管线。

`0x0030` 把角色基础属性的指定百分比写入原版“额外装备效果”槽，只在当前战斗生效。
同一角色同一属性再次执行时替换旧值，不会重复叠加；当前覆盖真实脚本使用的攻击、灵力、
防御、身法、逃跑和毒抗属性。operand 2 为 0 时使用脚本 owner，否则按一基角色编号
选择目标。`0x0031` 同样只在当前战斗覆盖目标角色的战斗 sprite，值 0 恢复开战时由装备
效果确定的 sprite。结算不会把这些临时效果写回长期角色属性。

非首领战的玩家逃跑也进入本回合敏捷队列；轮到角色时，以包含临时效果的逃跑率对全部
存活敌人的身法与等级总和进行原版随机判定。失败会消耗该角色行动并继续回合，成功才将
战斗结果设为逃跑。脚本 `0x003A` 是独立的强制逃跑路径，不使用这项随机判定。

### 战斗脚本状态修改

以下 M6 指令已经解码并连接到平台无关战斗状态：

- `0x0021`：对一个或全部敌人造成直接伤害。
- `0x0028..0x002F`：敌我施毒、按对象/等级解毒，以及设置或移除状态。
- `0x0030`、`0x0031`：按基础属性百分比施加临时强化，以及临时替换玩家战斗 sprite。
- `0x0033`、`0x0034`：累计敌人炼化值，并随机消耗 1..=9 点从商店 0 的对应槽生成物品。
- `0x0039`、`0x003A`：吸取敌人 HP 与尝试逃跑。
- `0x005C`、`0x006A`：按回合隐藏玩家，以及按敌人剩余数量偷取物品或金钱。
- `0x006B`：设置当前法术的有符号吹飞范围；玩家法术移动全部敌人，敌方法术移动全部玩家。
- `0x005A`、`0x005B`、`0x005F`、`0x0060`：玩家/敌人 HP 减半或立即归零。
- `0x005D`、`0x005E`、`0x0061`、`0x0064`：按毒和敌人 HP 百分比跳转。
- `0x0067`、`0x0069`：修改敌人施法参数，以及由敌方脚本终止战斗。
- `0x0042`、`0x0057`、`0x0066`、`0x0088`：模拟玩家法术、投掷武器，以及按剩余
  MP/金钱改写当前法术伤害。
- `0x0089`、`0x0091`：设置战斗结果，以及判断是否为首个同类存活敌人。
- `0x008A`：让下一场战斗为每名可行动角色在可负担攻击法术上叠加 `0..=9999` 随机权重；
  `F` 强制快捷键使用 `0..=60`，没有候选法术时改为普通攻击。MP 消耗为 1 的终极技不参与。
- `0x0092`：可选择一基队员播放预施法位移及第 5/6 帧，并对全队播放 `0..8` 的五步色移。
- `0x009C`、`0x009E`、`0x009F`：敌人分裂、召唤与变身；失败入口由脚本运行时跳转。

敌人实例同时保留法术、施法概率、法术帧和音效、攻击等效物品、偷窃物品、双行动、
炼化价值和法术抗性。三个生命周期脚本入口、敌人实际施法、混乱攻击同伴和普通攻击的
等效物品脚本已经接通。

敌人脚本 owner 使用原版五槽编号，运行时的稠密 actor 索引只供动作队列和渲染使用。
分裂仅在恰好一个存活敌人且其 HP 大于 1 时成功，新增副本数为 0 时按 1；共享 HP 按
`(原 HP + 请求副本数) / (请求副本数 + 1)` 计算，即使请求数超过剩余槽位也不改变除数。
副本继承当前敌人定义和三个生命周期脚本，但不继承状态与毒。召唤只填充当前布局边界内
的空槽，数量按有符号 word 解释且非正数按 1；隐藏或昏睡、麻痹、混乱会走失败入口。
变身替换对象及全部静态敌人字段并重载 sprite，保留当前 HP、状态、毒和三个生命周期
脚本。分裂扩大最高占用槽后，会按 DATA.MKF chunk 13 为全部存活敌人重新计算站位。
偷窃率为 0 时必定成功，否则按原版 `random(0..=10) <= rate` 判定；物品每次减少一件，
金钱按剩余量除以随机 2 或 3 取得。隐藏期间敌人跳过行动，完整回合结束后递减，隐藏未
结束时不执行敌人 turn-start 脚本。自动战斗在结算时清除，不影响下一场普通战斗。

战斗动作先产生平台无关事件，再由桌面层排队显示攻击位移、受击、伤害和死亡反馈；
吹飞范围随下一条法术伤害事件传递，桌面层在反馈阶段使用确定性随机序列累加位移，
反馈结束即恢复角色原始站位。全体法术的第一条目标事件独占预施法和完整特效，其余目标
只播放短受击反馈；吹飞量也只由第一条携带，不能为每个目标重播整段法术。

普通攻击法术的主体帧数按原版计算：`n + (n - fire_delay) * effect_times + shake`。
每帧持续 `(speed + 5) * 10ms`，桌面固定 50ms 更新步使用向上取整的总时长，并在渲染时
按累计毫秒选择帧；首次播放到 `fire_delay` 时触发法术音效，附加循环只重复
`fire_delay..n`。辅助法术只播放 `n` 帧，随后执行 `0..5, 6..0` 的目标色移。`wave`
只在主体阶段叠加，`shake` 占主体末尾的独立震屏阶段。

召唤类的 word 0 不是 `FIRE.MKF` 编号，而是另一条法术记录编号。运行时按原版从全局
对象表寻找第一个引用该编号的法术对象，先播放 `F.MKF` 的 `specific + 10` 召唤本体，
再用被引用法术的 FIRE sprite、坐标、层级、循环、震屏和波动参数播放真正攻击特效。
当实际特效的 `keep_effect == 0xFFFF` 时，最后一个非震屏帧按其全部位置写入本场战斗的
持久背景层；它在后续行动中继续显示，并在战斗开始或结束时清空。

`0x0092` 产生的 22 帧反馈会立即进入桌面战斗队列，队列清空前暂停当前战斗脚本。
混乱玩家攻击队友与混乱敌人攻击同伴使用各自角色的攻击/武器/受击音效。
胜负确定后仍保留战斗画面，胜利时切换普通战/首领战胜利曲并使用原版 sprite 单行框和文本
显示 EXP、金钱。普通战停留 3 秒，首领战停留 5.5 秒，任意按键可提前继续。随后先结算主
经验，再按本场攻击、防御、仙术、逃跑等行为次数分配生命、真气、武术、灵力、防御、身法、
逃跑七类隐藏经验；升级、隐藏属性成长和新习得仙术使用原版框体，每页停留 3 秒并可按任意键
提前继续。
最后每名队员恢复缺失 HP 与 MP 的一半，再恢复场景脚本。失败和逃跑不发放奖励。原版
收妖与炼化物品由 `0x0033`/`0x0034` 显式触发，
不是普通胜利的自动掉落；首战没有这类脚本。

## 边界要求

- 固定记录表必须非空并且长度是记录大小的整数倍。
- chunk 13 必须恰好 100 字节，chunk 14 必须恰好 200 字节。
- 敌队、敌人对象、敌人定义、战场和图像编号均在使用处再次验证。
- HP、伤害、经验和金钱运算使用饱和或扩宽整数，损坏数据不能造成溢出 panic。

## 仍待逐项对照

当前真实资源回归只能证明现有剧情片段可运行，以下 Classic 逻辑仍不能标记为完成：

- Repeat/Force/持续自动攻击在合体技之前已有已提交动作、角色中途恢复以及特殊目标切换时的
  剩余边界语义。
- 敌人死亡后原版清空槽位与当前稳定 actor 索引之间，所有脚本 opcode 的死槽目标行为。
- turn-start、毒和 battle-end 脚本主动改变战斗结果时，剩余脚本与胜负事件的精确停止点。
- 每种动作的帧级时序、命中反馈、召唤体消失和战场淡入淡出；这些表现差异不能由核心规则
  单元测试覆盖。

后续应继续以 `PAL_BattleStartFrame`、`PAL_BattlePlayerValidateAction`、
`PAL_BattlePlayerPerformAction`、`PAL_BattleEnemyPerformAction` 和
`PAL_BattlePostActionCheck` 为单位建立差异测试，不能再用“菜单可用”或“测试总数通过”代替
原版等价性判断。
