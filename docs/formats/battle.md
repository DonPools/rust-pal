# 战斗数据格式

## DATA.MKF 战斗表

当前 DOS 资源的战斗静态数据分布如下。所有数值均为 little-endian；带符号字段使用
`i16`，其余为 `u16`。

| Chunk | 记录大小 | 当前记录数 | 内容 |
|---:|---:|---:|---|
| 1 | 70 字节 | 154 | 敌人属性和动画参数 |
| 2 | 10 字节 | 380 | 每队最多五个敌人对象 ID |
| 5 | 12 字节 | 65 | 战场波动和五系法术修正 |
| 6 | 20 字节 | 20 | 五名可入队角色的升级习得法术 |
| 13 | 100 字节 | 1 | 按敌人数和槽位组织的战斗站位 |
| 14 | 200 字节 | 1 | 0..99 级升级经验阈值 |

### 敌人记录

敌人记录包含 35 个 word：

| Word | 字段 |
|---:|---|
| 0..4 | 待机帧、法术帧、攻击帧、待机速度、动作等待帧 |
| 5 | Y 坐标偏移 |
| 6..10 | 攻击、动作、法术、死亡和登场音效，按 `i16` 读取 |
| 11..16 | HP、经验、金钱、等级、法术编号和施法概率 |
| 17..20 | 攻击等效物品及概率、偷窃物品及数量 |
| 21..26 | 攻击、灵力、防御、身法、逃跑和毒抗 |
| 27..31 | 五系抗性 |
| 32..34 | 物理抗性、双行动标记和炼化价值 |

敌队中的值是 `SSS.MKF` 全局对象 ID，不是 chunk 1 的直接索引。敌人对象的字段 0
才是 chunk 1 敌人编号，同时也是 `ABC.MKF` 的敌人 sprite 编号。值 `0xFFFF` 表示
队伍布局结束；值 `0` 是空槽。使用时必须依次验证敌队、全局对象和敌人定义索引。

### 敌人站位

chunk 13 是 `5 x 5` 个 `(x, y)` 坐标。第一维是敌人槽位，第二维是布局槽数减一。
尾部 `0xFFFF` 不计入布局槽数，值为 0 的空槽仍保留其位置。

### 攻击法术记录

`DATA.MKF` chunk 4 的法术记录固定为 16 个 word。M5 战斗使用以下字段：

| Word | 字段 |
|---:|---|
| 0 | 效果 sprite 编号 |
| 1 | 法术类型；0 为单体，1..3 为不同全体表现 |
| 12 | MP 消耗 |
| 13 | 基础伤害 |
| 14 | 五系编号；0 表示无属性 |
| 15 | 音效编号，按 `i16` 读取 |

MP 消耗从 byte 24 开始，不能与 byte 26 的基础伤害互换。对象表中的法术对象先通过
字段 0 取得这里的法术编号。

## 图像资源

- `ABC.MKF`：敌人 GOP sprite；编号来自敌人对象字段 0。
- `F.MKF`：玩家战斗 GOP sprite；编号来自 `PLAYERROLES.rgwSpriteNumInBattle`。
- `FBP.MKF`：`320 x 200` 战场背景；编号由脚本 `0x004A` 设置。

这些资源可能直接保存 GOP/RLE，也可能经过 YJ_1 压缩；解码时保留 MKF 原始编号，
空 chunk 或格式错误不能改变后续索引。

## 脚本入口与首战基线

`0x0007` 的三个 operand 分别为敌队编号、失败跳转和逃跑跳转。operand 2 为 0 时按
不可逃跑的首领战处理。执行器在战斗期间暂停调用方脚本，胜利继续下一条，失败或逃跑
在对应入口非零时跳转。

当前真实资源中，场景 1 的事件对象 28 从 entry 6906 启动战前过场，随后自然执行到
entry 6965 的首场剧情战斗：

```text
6963  SET_PARTY    1, 2, 0
6964  BATTLEFIELD  21
6965  BATTLE       18, 40091, 0
6966  MUSIC        24, 3, 0
```

敌队 18 是两个对象 495（“苗人拳”），胜利后继续 entry 6966，失败跳到 40091，
不能逃跑。

开战前按六名角色和六个装备栏重放装备脚本，以重建攻击、防御、战斗精灵和音效等
派生字段。部分初始饰品还设置临时战斗状态；这些状态和角色身上的毒会在创建战斗时复制
到战斗实例，并在结算时写回长期游戏状态。开发快照保存六名角色的状态、每人 16 个毒槽
和炼化累计值；读取 DOS/Win95 原版存档时，毒槽按存档中的队伍位置映射回角色。

### 状态与毒

DOS/Classic 的状态编号为 0..8，依次是混乱、麻痹、昏睡、封咒、傀儡、勇敢、保护、
加速和双击。负面状态已存在时不延长；傀儡只对死亡角色生效；正面状态保留较长持续
时间。装备脚本使用大于 999 的持续时间，普通移除指令不能清除。每个完整回合结束后，
玩家和敌人的状态持续时间各减一。

当前战斗规则已接入昏睡/麻痹跳过行动、封咒禁止施法、傀儡维持死亡角色战斗资格、
勇敢物理暴击、保护减伤、双击和敌人双行动。玩家先完成本回合指令选择，随后敌我行动
按实际敏捷和 `90%..=110%` 的随机扰动降序执行；DOS/Classic 的加速状态会把玩家敏捷
乘以 3，上限为 999，濒死状态再减半。混乱玩家不进入指令选择，若未濒死则随机攻击一名
存活队友；混乱敌人会随机选择一名存活敌人攻击，若选中自己则放弃本次行动。

玩家和敌人各有 16 个毒槽，每槽保存毒对象 ID 与下一次脚本入口。毒对象复用全局对象
记录：word 0 是毒等级，word 1 是显示颜色，word 2 是玩家脚本，word 4 是敌人脚本。
添加时拒绝对象 0、避免重复并遵守玩家毒抗或敌人法术抗性；解毒可按对象或毒等级执行。
新毒添加后立即排入其首次脚本；每个完整回合按“玩家毒 -> 敌人毒 -> 状态递减”的顺序
重放。脚本可以跨帧暂停于对话、延时和视觉事件，完成后返回的 `next_entry` 会写回对应
毒槽，供下一回合继续。离开战斗时按原版清除持续时间不超过 999 的临时状态和等级不
超过 3 的毒；装备脚本状态与更高等级毒继续保留。

敌人的生命周期脚本也使用同一调度器：开战先按敌人顺序执行 turn-start；每次敌人行动
前执行 ready（双行动会执行两次）；回合毒与状态处理后再次执行 turn-start；胜利后、
结算前执行 battle-end。敌人按记录中的概率施放法术，封咒会强制改为普通攻击；法术的
use 和 success 脚本以目标角色 ID 执行并分别写回下一入口。use 脚本失败时跳过 success
脚本，但原版的基础伤害仍会结算。非单体类型攻击全部存活玩家，五系、毒抗、战场修正
和保护状态参与减伤。普通攻击后，攻击等效物品先按记录中的十分比概率判定，再要求
`1..=100` 的随机值大于目标毒抗；命中后以目标角色 ID 执行物品 use 脚本，并将返回的
下一入口写回对应物品对象。ready 脚本执行时不视为敌方行动，法术和攻击等效物品脚本
执行期间才满足 `0x0068` 的敌方回合条件。脚本造成的 HP、状态和毒变化以活动战斗实例
为准，并同步回角色长期状态。原版结果 `0` 作为独立的“脚本终止”结果处理：不发奖励，
也不走失败/逃跑跳转，但会让调用方剧情继续。

玩家攻击法术在敏捷队列轮到施法者时扣除 MP，再按“use 脚本 -> success 脚本 -> 伤害”
执行。use 失败会跳过动画、success 和伤害；success 的成功状态不阻止原版基础伤害。
`0x0057` 会用扣除施法消耗后的剩余 MP 乘以指定倍率（0 按 8）改写当前法术伤害并清空
MP；`0x0088` 最多消耗 5000 金钱，并按 `cash * 2 / 5` 改写当前法术伤害。两个脚本入口
分别返回后，法术的 use/success 入口都会持久化各自的下一入口。`0x0042` 使用 operand 1
作为模拟施法强度，并叠加法术定义中的基础伤害；单体目标失效时自动改选存活敌人，全体
法术遍历全部存活敌人。

玩家战斗物品分为使用和投掷两套列表。提交指令时，消耗型使用物品与所有投掷物品会
按物品 ID 预留库存，避免同一回合多名角色重复选择最后一个物品；真正轮到角色且物品
脚本完成后才扣除。角色在行动前死亡或失能时不消耗。使用脚本以目标角色 ID 为 owner，
作用全体时为 `0xFFFF`；消耗型使用物品不受脚本成功标记影响，执行后总是扣除一个，
非消耗型不扣。投掷脚本以敌人槽位为 owner，作用全体时为 `0xFFFF`，执行后总是扣除。
两种脚本返回的下一入口分别持久化，开发快照版本 18 保存投掷入口覆盖。

`0x0066` 只在投掷物品脚本内生效。它以 operand 0 选择模拟法术，强度为
`operand1 * 5 + acting_player.attack_strength * random(0..=3)`，目标沿用当前投掷脚本
owner，并复用模拟玩家法术的全体目标、抗性、战场修正和伤害反馈管线。

`0x0030` 把角色基础属性的指定百分比写入原版“额外装备效果”槽，只在当前战斗生效。
同一角色同一属性再次执行时替换旧值，不会重复叠加；当前覆盖真实脚本使用的攻击、灵力、
防御、身法、逃跑和毒抗属性。operand 2 为 0 时使用脚本 owner，否则按一基角色编号
选择目标。`0x0031` 同样只在当前战斗覆盖目标角色的战斗 sprite，值 0 恢复开战时由装备
效果确定的 sprite。结算不会把这些临时效果写回长期角色属性。

非首领战的玩家逃跑也进入本回合敏捷队列；轮到角色时，以包含临时效果的逃跑率对全部
存活敌人的身法与等级总和进行原版随机判定。失败会消耗该角色行动并继续回合，成功才将
战斗结果设为逃跑。脚本 `0x003A` 是独立的强制逃跑路径，不使用这项随机判定。

### 战斗脚本状态修改

以下 M6 指令已经解码并连接到平台无关战斗状态：

- `0x0021`：对一个或全部敌人造成直接伤害。
- `0x0028..0x002F`：敌我施毒、按对象/等级解毒，以及设置或移除状态。
- `0x0030`、`0x0031`：按基础属性百分比施加临时强化，以及临时替换玩家战斗 sprite。
- `0x0033`、`0x0034`：累计敌人炼化值，并随机消耗 1..=9 点从商店 0 的对应槽生成物品。
- `0x0039`、`0x003A`：吸取敌人 HP 与尝试逃跑。
- `0x005C`、`0x006A`：按回合隐藏玩家，以及按敌人剩余数量偷取物品或金钱。
- `0x005A`、`0x005B`、`0x005F`、`0x0060`：玩家/敌人 HP 减半或立即归零。
- `0x005D`、`0x005E`、`0x0061`、`0x0064`：按毒和敌人 HP 百分比跳转。
- `0x0067`、`0x0069`：修改敌人施法参数，以及由敌方脚本终止战斗。
- `0x0042`、`0x0057`、`0x0066`、`0x0088`：模拟玩家法术、投掷武器，以及按剩余
  MP/金钱改写当前法术伤害。
- `0x0089`、`0x0091`：设置战斗结果，以及判断是否为首个同类存活敌人。
- `0x008A`：让下一场战斗自动为每名可行动角色选择最高基础伤害的可负担法术或普通攻击。
- `0x009C`、`0x009E`、`0x009F`：敌人分裂、召唤与变身；失败入口由脚本运行时跳转。

敌人实例同时保留法术、施法概率、法术帧和音效、攻击等效物品、偷窃物品、双行动、
炼化价值和法术抗性。三个生命周期脚本入口、敌人实际施法、混乱攻击同伴和普通攻击的
等效物品脚本已经接通。

敌人脚本 owner 使用原版五槽编号，运行时的稠密 actor 索引只供动作队列和渲染使用。
分裂仅在恰好一个存活敌人且其 HP 大于 1 时成功，新增副本数为 0 时按 1；共享 HP 按
`(原 HP + 请求副本数) / (请求副本数 + 1)` 计算，即使请求数超过剩余槽位也不改变除数。
副本继承当前敌人定义和三个生命周期脚本，但不继承状态与毒。召唤只填充当前布局边界内
的空槽，数量按有符号 word 解释且非正数按 1；隐藏或昏睡、麻痹、混乱会走失败入口。
变身替换对象及全部静态敌人字段并重载 sprite，保留当前 HP、状态、毒和三个生命周期
脚本。分裂扩大最高占用槽后，会按 DATA.MKF chunk 13 为全部存活敌人重新计算站位。
偷窃率为 0 时必定成功，否则按原版 `random(0..=10) <= rate` 判定；物品每次减少一件，
金钱按剩余量除以随机 2 或 3 取得。隐藏期间敌人跳过行动，完整回合结束后递减，隐藏未
结束时不执行敌人 turn-start 脚本。自动战斗在结算时清除，不影响下一场普通战斗。

战斗动作先产生平台无关事件，再由桌面层排队显示攻击位移、受击、伤害和死亡反馈；
混乱玩家攻击队友与混乱敌人攻击同伴使用各自角色的攻击/武器/受击音效。
胜负确定后仍保留战斗画面，玩家确认 EXP/金钱结算后才提交 HP、MP、成长和金钱并恢复
场景脚本。失败和逃跑不发放奖励。原版收妖与炼化物品由 `0x0033`/`0x0034` 显式触发，
不是普通胜利的自动掉落；首战没有这类脚本。

## 边界要求

- 固定记录表必须非空并且长度是记录大小的整数倍。
- chunk 13 必须恰好 100 字节，chunk 14 必须恰好 200 字节。
- 敌队、敌人对象、敌人定义、战场和图像编号均在使用处再次验证。
- HP、伤害、经验和金钱运算使用饱和或扩宽整数，损坏数据不能造成溢出 panic。
