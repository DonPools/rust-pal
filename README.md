# Rust-PAL

《仙剑奇侠传》（Legend of Sword and Fairy）的 Rust 重实现。项目以 SDLPAL
作为行为参考，从原版数据文件中加载资源，不包含原始游戏代码或数据。

项目仍处于早期阶段。当前已形成从可交互场景进入首场真实战斗、完成结算并继续剧情的
最小闭环，可以移动、触发脚本、阅读对话、管理物品与装备、施放场景法术并进行战斗。

## 架构

代码按职责分层，依赖方向保持单向：

```text
pal-launcher -> pal-desktop -> pal-core -> pal-assets
       |              |            |
       +--------------+------------+
```

实际依赖会跳过中间层，例如 launcher 可以直接使用 core 和 assets，但底层 crate
不能反向依赖平台层。

| Crate | 职责 | 主要边界 |
|---|---|---|
| `pal-assets` | 二进制资源格式解析与解码 | 不包含游戏规则和平台代码 |
| `pal-core` | 世界状态、角色、场景、脚本和战斗规则 | 不依赖窗口、输入和音频后端 |
| `pal-desktop` | 窗口、输入、音频与 framebuffer 呈现 | 将平台事件转换为 core 可理解的命令 |
| `pal-launcher` | 数据路径、启动参数和各层装配 | 不承载长期游戏状态或规则 |

桌面运行时进一步分为平台 host 和应用状态两层。`window/mod.rs` 只负责 `winit`/`pixels`
窗口事件、surface 调整和 framebuffer 呈现；`DesktopApp` 持有游戏、脚本、输入、表现和
固定时间步状态。更新顺序由显式 `UpdateLane` 状态机决定，开场阶段由 `FrontendState`
保证互斥，活动菜单由单一 `ActiveMenu` 表示。桌面会话按脚本、菜单、战斗表现、音频、
视觉和持久化分组，避免平台事件循环直接组合非法状态。

```text
winit event -> DesktopApp::advance -> UpdateLane -> core/script/battle/menu
                  |                       |
                  +---- render_frame <----+
                            |
                       pixels present
```

分层用于控制代码依赖，开发计划则按可运行的玩家体验组织。每个里程碑都会同时涉及
资源、核心逻辑、平台适配和表现层，而不是先完成一个系统再开始下一个系统。

## 持续工作轨道

以下工作贯穿所有里程碑，不单独作为阻塞后续开发的线性阶段：

| 轨道 | 工作方式 |
|---|---|
| 格式研究 | 研究当前里程碑需要的数据格式，并同步到 `docs/formats/` |
| 核心模型 | 保持世界更新确定、平台无关，并为规则增加内存 fixture 测试 |
| 平台适配 | 提供时间、输入、窗口和音频后端，不把业务规则放入事件循环 |
| 表现层 | 按可玩片段增加地图、角色、UI、动画和音效能力 |
| 验证 | 同时维护单元测试、真实资源检查和阶段性手工 smoke test |

新功能应尽量服务于当前里程碑的端到端闭环。格式解析或系统抽象只有在真实内容需要时
才扩展，避免提前实现彼此尚未连接的大型子系统。

## 构建与运行

需要 Rust 工具链以及用户自行提供的正版游戏数据。将至少以下文件放入 workspace
根目录的 `data/`：

```text
PAT.MKF
MAP.MKF
GOP.MKF
FBP.MKF
RNG.MKF
MGO.MKF
RGM.MKF
DATA.MKF
SSS.MKF
VOC.MKF
MUS.MKF
WORD.DAT
M.MSG
WOR16.ASC
WOR16.FON
```

RIX/OPL2 背景音乐直接来自 `MUS.MKF`，不需要外部音色库。默认优先选择 MIDI，所需的
`data/MIDI.MKF` 和 `data/TimGM6mb.sf2` 缺失或无效时会明确告警并固定使用 RIX，不会在
单曲播放中静默换音源。`TimGM6mb.sf2` 可以来自 Debian 的 `timgm6mb-soundfont` 包，也可
用其他兼容 GM 的 SF2 替换；该文件不嵌入 binary 或仓库。

构建并启动游戏：

```shell
cargo build
cargo run -p pal-launcher
```

启动时可用 `--music=midi` 或 `--music=rix` 指定初始后端；自定义音色库使用
`--sound-font=/path/to/custom.sf2`。系统菜单也可在 `OFF / MIDI / RIX` 之间切换。

运行时按 `F3` 切换碰撞调试，红色菱形为阻挡 tile，绿色菱形为可通行 tile，黄色十字
为玩家实际参与碰撞检测的逻辑坐标；按 `F4` 切换事件对象调试，所有对象显示小十字，
橙色表示触发脚本、青色表示自动脚本、品红色表示两者兼有，灰色表示无脚本或隐藏状态，
当前脚本对象显示白色 `#ID`；按 `F6` 切换右上角脚本 inspector。脚本 inspector 显示
场景、玩家、脚本 owner、触发类型、entry、opcode、三个参数、调用深度和等待帧，以及当前
对象的位置、状态、层级、触发模式、sprite、动画帧、方向、可见性和阻挡能力，脚本
结束后保留最近一条指令便于检查。`0xffff` 的系统脚本显示为 `SYSTEM`，不会映射成场景对象。
按 `F7` 切换窗口右上角的半透明紧凑战斗调试面板；简体中文信息卡显示当前表现事件、最近一次
伤害的扣血前后值与死亡标记，以及敌人的对象/定义编号、原始和有符号 HP、Classic 有效
攻击/防御、模拟仙术防御、抗性与队员战斗属性。面板优先使用系统中文字体，也可通过
`RUST_PAL_DEBUG_FONT=/path/to/font.ttf` 指定字体文件。
自由探索时右上角会显示独立于游戏像素分辨率的半透明小地图，并随窗口尺寸在小屏与全屏间
动态缩放；亮色箭头表示玩家位置和朝向，橙色点表示当前可见的可交互对象。按 `M` 可以显示
或隐藏小地图；开场、战斗、菜单、对话和脚本演出期间会自动隐藏。

探索时按 `Esc` 或 `Backspace` 打开原版顺序的场景主菜单。状态、仙术、物品使用和装备
入口已接通。物品列表按原版三列布局：左右逐项、
上下跨三项；单体物品会继续选择队员并可连续使用，全体物品使用后退出菜单。灰色物品当前
不可在场景中使用，取消目标选择返回物品列表，取消物品列表关闭整套场景菜单。

进入战斗后，方向键按原版十字布局选择攻击、仙术、合体和其他图标，Enter 或空格确认；
单体攻击、攻击仙术和合体技确认后再选择敌人，辅助仙术和使用物品可选择队员；全体目标
会直接提交。其他菜单包含自动、物品、防御、逃跑和状态，物品再分使用与投掷。Esc 或
Backspace 返回上一级；在主指令状态会撤销上一名队员的指令和物品预留。战斗快捷键为
`R` 重复、`A` 自动攻击、`D` 防御、`E` 使用物品、`W` 投掷、`Q` 全队逃跑、`S` 状态、
`F` 本回合全队强制攻击法术。动作反馈期间暂不接受新指令；战斗状态入口显示完整原版状态页。
胜利奖励页普通战停留 3 秒、首领战 5.5 秒，升级/属性成长和新习得仙术页面各停留 3 秒；
所有页面都可按任意键提前继续，然后自动返回场景。

没有运行剧情脚本或显示对话时，按 `F5` 捕获运行期开发状态快照，按 `F9` 恢复。
快照包含玩家、队伍、物品、音乐和已访问场景状态，并通过临时文件写入 workspace 根目录的
`rust-pal.snapshot.json`。该开发格式带版本号，不承诺与最终原版兼容存档格式一致。
系统菜单中的存储和读取均显示原版 1–5 槽界面。存储会将当前状态写成可重新读取的原版
`.rpg` 文件，并把五槽最大保存次数加一；读取选定槽后停止音乐、淡出并恢复场景。槽位会
查找 `data/1.RPG` 至 `data/5.RPG`（也接受小写扩展名）及 `data/SAVES/` 下的同名文件，
新存档写入 `data/{slot}.RPG`。启动时会先播放原版商标和标题动画，再显示开场背景；可
选择新游戏或进入同一套 1–5 槽读取菜单。

系统菜单的“音乐”行进入 `OFF / MIDI / RIX` 三选框，“音效”行进入“禁用 / 启用”
二选框，默认停在当前状态；确认后立即应用，取消则返回系统菜单。退出游戏使用默认选择
“否”的“否 / 是”确认框，选择“是”后淡出。音乐脚本可在同一曲目播放过程中改变是否循环，
无需从头重播。

执行不打开窗口的真实资源检查：

```shell
cargo run -p pal-launcher -- --check-assets
```

完整开发检查：

```shell
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

`data/` 和 `reference/` 均被忽略，不应提交其中的版权资源或参考实现副本。

## 目录结构

```text
rust-pal/
├── pal-assets/       # MKF、palette、RLE、sprite、YJ_1 等资源解析
├── pal-core/         # 平台无关的地图、角色和后续游戏状态
├── pal-desktop/      # winit 窗口、pixels framebuffer 和桌面适配
├── pal-launcher/     # 桌面程序入口与装配
├── docs/formats/     # 已研究的数据格式文档
├── data/             # 本地原版游戏资源，不纳入版本控制
└── reference/        # 本地参考实现，不纳入版本控制
```

## 技术选择

- `winit`：跨平台窗口与事件循环
- `pixels`：呈现固定 `320x200` RGBA framebuffer
- `nuked-opl3`：纯 Rust、无 FFI 的 OPL2/OPL3 芯片模拟，播放 DOS `MUS.MKF` RIX 音乐
- `rustysynth`：使用可替换的 General MIDI SoundFont 合成 `MIDI.MKF`
- `rodio`：输出合成后的 `44100 Hz` 立体声 PCM 和 VOC 音效
- 纯 Rust YJ_1：避免依赖预编译对象或 C FFI，并对不可信输入执行边界检查
