# Rust-PAL

《仙剑奇侠传》（Legend of Sword and Fairy）的 Rust 重实现。项目以 SDLPAL
作为行为参考，从原版数据文件中加载资源，不包含原始游戏代码或数据。

项目仍处于早期阶段。当前已形成可交互场景闭环，可以在真实地图中移动角色、触发
事件脚本、阅读对话、获得物品、查看物品菜单并切换场景；音频和战斗尚未实现。

## 当前能力

- [x] 解析 MKF、palette、RLE bitmap、GOP sprite 和 YJ_1 压缩数据
- [x] 加载原版 `MAP.MKF` 地图和 `GOP.MKF` 地图图块
- [x] 使用 `winit` + `pixels` 创建 `320x200` 索引色风格的桌面画面
- [x] 按地图顺序绘制底层图块、角色精灵和顶层遮挡
- [x] 使用真实游戏数据执行无窗口资源与 framebuffer 检查
- [x] 持续运行的固定时间步、输入和世界状态更新
- [x] 玩家移动、地图碰撞、步行动画和相机跟随
- [x] 从场景进入脚本解析队伍初始落点
- [x] 当前场景事件对象的加载、渲染、可见状态和阻挡
- [x] 加载 Big5 文本资源和原版 16x15 位图字库
- [x] 事件触发、基础对话和最小脚本运行时
- [x] 场景进入脚本、物品获得和场景切换
- [x] 加载初始队伍、完整基础角色属性和全局对象定义
- [x] 解码并播放 `VOC.MKF` 场景音效
- [x] 基础物品菜单
- [ ] 音频和战斗

当前产物应视为“可交互场景原型”，还不是完整游戏。

## 架构

代码按职责分层，依赖方向保持单向：

```text
pal-launcher -> pal-desktop -> pal-core -> pal-assets
       |              |            |
       +--------------+------------+
```

实际依赖会跳过中间层，例如 launcher 可以直接使用 core 和 assets，但底层 crate
不能反向依赖平台层。

| Crate | 职责 | 主要边界 |
|---|---|---|
| `pal-assets` | 二进制资源格式解析与解码 | 不包含游戏规则和平台代码 |
| `pal-core` | 世界状态、角色、场景、脚本和战斗规则 | 不依赖窗口、输入和音频后端 |
| `pal-desktop` | 窗口、输入、音频与 framebuffer 呈现 | 将平台事件转换为 core 可理解的命令 |
| `pal-launcher` | 数据路径、启动参数和各层装配 | 不承载长期游戏状态或规则 |

分层用于控制代码依赖，开发计划则按可运行的玩家体验组织。每个里程碑都会同时涉及
资源、核心逻辑、平台适配和表现层，而不是先完成一个系统再开始下一个系统。

## 开发路线

### M0：静态场景渲染基线

目标：证明真实资源能够通过完整的解析和渲染管线显示。

- [x] 加载 palette、地图图块和角色 sprite
- [x] 实现地图坐标、viewport 和负坐标裁剪
- [x] 完成底层图块、角色和顶层图块的绘制顺序
- [x] 通过 `--check-assets` 验证非空、非灰度 framebuffer 和角色绘制

验收：能够打开一个真实场景，角色正确出现在地图中并被前景图块遮挡。

### M1：可探索场景

目标：建立第一个完整的实时游戏闭环。

```text
输入 -> 固定时间步 -> 世界更新 -> 碰撞与动画 -> 相机 -> 场景渲染
```

- [x] 由 `pal-core` 持有可持续更新的 `GameState`
- [x] 增加固定时间步和明确的 update/render 边界
- [x] 将键盘状态映射为方向、确认、取消等游戏命令
- [x] 实现玩家移动、朝向和步行动画
- [x] 使用地图阻挡信息处理移动碰撞
- [x] 实现相机跟随和地图边界约束
- [x] 为移动、碰撞和相机增加不依赖窗口的测试

验收：玩家可以在真实场景中稳定行走，不能穿过阻挡区域，相机与动画正确更新。

### M2：可交互场景

目标：让探索能够触发并完成一段最小交互。

- [x] 解析 `SSS.MKF` 中当前场景所需的场景和事件对象数据
- [x] 渲染事件对象并处理动画、碰撞和可见状态
- [x] 支持接触触发和面前交互
- [x] 加载字库、`WORD.DAT` 与 `M.MSG`，绘制 Big5 位图文本
- [x] 将脚本消息接入对话框，确认键逐条继续
- [x] 支持长消息三行分页
- [x] 支持上方、下方、居中和居中窗口四种基础对话位置
- [x] 实现脚本记录解析器和可暂停的最小触发脚本运行时
- [x] 实现场景对象状态、位置、动作、玩家位移和等待等基础 opcode
- [x] 实现物品获得、队伍定位和场景切换 opcode
- [x] 启动和切换后执行场景进入脚本
- [x] 真实资源检查覆盖完整进入对话、拾取物品和离开当前场景

验收：玩家可以接近一个真实事件对象，触发脚本、阅读对话，并在脚本结束后继续探索。

`M.MSG` 保存消息文本；脚本记录及入口主要来自 `SSS.MKF` 和其他对象数据。对话系统
与脚本运行时因此需要共同推进。

### M3：第一段连续剧情

目标：从启动开始完成一段可重复验证的真实剧情流程。

- [x] 加载队伍、角色属性和全局对象定义
- [x] 支持剧情需要的对象移动、场景修改和队伍变化
- [x] 实现基础菜单以及物品获得、失去和查看
- [ ] 播放场景 BGM（关键 VOC 音效已接入）
- [ ] 持久化剧情变量和场景状态
- [ ] 增加最小存档，或先提供等价的开发状态快照

验收：可以连续完成选定剧情片段；重新进入场景或恢复状态后，已发生的变化不会重置。

### M4：第一次完整战斗

目标：完成“场景触发战斗 -> 战斗结算 -> 返回场景”的闭环。

- [ ] 从场景或脚本创建战斗状态
- [ ] 初始化敌我双方和基础属性
- [ ] 实现最小指令选择、普通攻击、伤害和死亡判定
- [ ] 实现胜负、经验和物品结算
- [ ] 添加必要的战斗 UI、动画、音效和脚本钩子
- [ ] 结算后恢复场景世界状态

验收：一场由真实数据驱动的战斗能够开始、结束、结算并正确返回原场景。

### M5：兼容性扩展

目标：在已有可玩闭环上逐项扩大原版内容覆盖面。

- [ ] 扩展脚本 opcode 和跨场景剧情覆盖
- [ ] 完善原版对话布局、头像、逐字显示和文本控制符
- [ ] 完善物品、装备、法术、商店和角色成长
- [ ] 完善战斗指令、状态、毒、敌人行为和特效
- [ ] 支持调色板动画、过场动画和 RNG 动画
- [ ] 完善 MIDI、VOC 等原版音频资源支持
- [ ] 增加存档兼容性和更长流程的回归验证

该里程碑不是单次“完成全部系统”，而是以可验证的剧情和战斗片段持续迭代。

## 持续工作轨道

以下工作贯穿所有里程碑，不单独作为阻塞后续开发的线性阶段：

| 轨道 | 工作方式 |
|---|---|
| 格式研究 | 研究当前里程碑需要的数据格式，并同步到 `docs/formats/` |
| 核心模型 | 保持世界更新确定、平台无关，并为规则增加内存 fixture 测试 |
| 平台适配 | 提供时间、输入、窗口和音频后端，不把业务规则放入事件循环 |
| 表现层 | 按可玩片段增加地图、角色、UI、动画和音效能力 |
| 验证 | 同时维护单元测试、真实资源检查和阶段性手工 smoke test |

新功能应尽量服务于当前里程碑的端到端闭环。格式解析或系统抽象只有在真实内容需要时
才扩展，避免提前实现彼此尚未连接的大型子系统。

## 构建与运行

需要 Rust 工具链以及用户自行提供的正版游戏数据。将至少以下文件放入 workspace
根目录的 `data/`：

```text
PAT.MKF
MAP.MKF
GOP.MKF
MGO.MKF
DATA.MKF
SSS.MKF
```

构建并打开当前场景查看器：

```shell
cargo build
cargo run -p pal-launcher
```

运行时按 `F3` 可切换碰撞调试层：红色菱形为阻挡 tile，绿色菱形为可通行 tile，
黄色十字为玩家实际参与碰撞检测的逻辑坐标。

探索时按 `Esc` 或 `Backspace` 打开物品菜单，使用上下方向键选择物品，再次按取消键
关闭菜单。

执行不打开窗口的真实资源检查：

```shell
cargo run -p pal-launcher -- --check-assets
```

完整开发检查：

```shell
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

`data/` 和 `reference/` 均被忽略，不应提交其中的版权资源或参考实现副本。

## 目录结构

```text
rust-pal/
├── pal-assets/       # MKF、palette、RLE、sprite、YJ_1 等资源解析
├── pal-core/         # 平台无关的地图、角色和后续游戏状态
├── pal-desktop/      # winit 窗口、pixels framebuffer 和桌面适配
├── pal-launcher/     # 桌面程序入口与装配
├── docs/formats/     # 已研究的数据格式文档
├── data/             # 本地原版游戏资源，不纳入版本控制
└── reference/        # 本地参考实现，不纳入版本控制
```

## 技术选择

- `winit`：跨平台窗口与事件循环
- `pixels`：呈现固定 `320x200` RGBA framebuffer
- `rodio`：桌面 PCM 音效输出；MIDI/RIX 背景音乐合成尚未接入
- 纯 Rust YJ_1：避免依赖预编译对象或 C FFI，并对不可信输入执行边界检查
