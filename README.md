# Rust-PAL

《仙剑奇侠传》（Legend of Sword and Fairy）的 Rust 重实现。项目以 SDLPAL
作为行为参考，从原版数据文件中加载资源，不包含原始游戏代码或数据。

项目仍处于早期阶段。当前已形成可交互场景闭环，可以在真实地图中移动角色、触发
事件脚本、阅读对话、获得物品、查看物品菜单、切换场景并播放音频；战斗尚未实现。

- [x] 按地图顺序绘制底层图块、角色精灵和顶层遮挡
- [x] 使用真实游戏数据执行无窗口资源与 framebuffer 检查
- [x] 持续运行的固定时间步、输入和世界状态更新
- [x] 玩家移动、地图碰撞、步行动画和相机跟随
- [x] 从场景进入脚本解析队伍初始落点
- [x] 当前场景事件对象的加载、渲染、可见状态和阻挡
- [x] 当前场景事件对象自动脚本调度和开场出口启用
- [x] 加载 Big5 文本资源和原版 16x15 位图字库
- [x] 事件触发、基础对话和最小脚本运行时
- [x] 场景进入脚本、物品获得和场景切换

- [x] 基础物品菜单

- [x] 从背包选择队员并使用 HP、MP 和复活类物品

M3 已完成，M4 正在推进物品使用和剧情阻塞脚本；战斗系统尚未开始。

## 架构

代码按职责分层，依赖方向保持单向：

```text
pal-launcher -> pal-desktop -> pal-core -> pal-assets
       |              |            |
       +--------------+------------+
```

实际依赖会跳过中间层，例如 launcher 可以直接使用 core 和 assets，但底层 crate
不能反向依赖平台层。

| Crate | 职责 | 主要边界 |
|---|---|---|
| `pal-assets` | 二进制资源格式解析与解码 | 不包含游戏规则和平台代码 |
| `pal-core` | 世界状态、角色、场景、脚本和战斗规则 | 不依赖窗口、输入和音频后端 |
| `pal-desktop` | 窗口、输入、音频与 framebuffer 呈现 | 将平台事件转换为 core 可理解的命令 |
| `pal-launcher` | 数据路径、启动参数和各层装配 | 不承载长期游戏状态或规则 |

分层用于控制代码依赖，开发计划则按可运行的玩家体验组织。每个里程碑都会同时涉及
资源、核心逻辑、平台适配和表现层，而不是先完成一个系统再开始下一个系统。

## 开发路线

### M0：静态场景渲染基线

目标：证明真实资源能够通过完整的解析和渲染管线显示。

- [x] 加载 palette、地图图块和角色 sprite
- [x] 实现地图坐标、viewport 和负坐标裁剪
- [x] 完成底层图块、角色和顶层图块的绘制顺序
- [x] 通过 `--check-assets` 验证非空、非灰度 framebuffer 和角色绘制

验收：能够打开一个真实场景，角色正确出现在地图中并被前景图块遮挡。

### M1：可探索场景

目标：建立第一个完整的实时游戏闭环。

```text
输入 -> 固定时间步 -> 世界更新 -> 碰撞与动画 -> 相机 -> 场景渲染
```

- [x] 由 `pal-core` 持有可持续更新的 `GameState`
- [x] 增加固定时间步和明确的 update/render 边界
- [x] 将键盘状态映射为方向、确认、取消等游戏命令
- [x] 实现玩家移动、朝向和步行动画
- [x] 使用地图阻挡信息处理移动碰撞
- [x] 实现相机跟随和地图边界约束
- [x] 为移动、碰撞和相机增加不依赖窗口的测试

验收：玩家可以在真实场景中稳定行走，不能穿过阻挡区域，相机与动画正确更新。

### M2：可交互场景

目标：让探索能够触发并完成一段最小交互。

- [x] 解析 `SSS.MKF` 中当前场景所需的场景和事件对象数据
- [x] 渲染事件对象并处理动画、碰撞和可见状态
- [x] 支持接触触发和面前交互
- [x] 加载字库、`WORD.DAT` 与 `M.MSG`，绘制 Big5 位图文本
- [x] 将脚本消息接入对话框，确认键逐条继续
- [x] 支持原版四行分页、连续消息和说话人标题
- [x] 支持上方、下方、居中和居中窗口布局、字色与头像
- [x] 实现脚本记录解析器和可暂停的最小触发脚本运行时
- [x] 实现场景对象状态、位置、动作、玩家位移和等待等基础 opcode
- [x] 实现物品获得、队伍定位和场景切换 opcode
- [x] 启动和切换后执行场景进入脚本
- [x] 真实资源检查覆盖完整进入对话、拾取物品和离开当前场景

验收：玩家可以接近一个真实事件对象，触发脚本、阅读对话，并在脚本结束后继续探索。

`M.MSG` 保存消息文本；脚本记录及入口主要来自 `SSS.MKF` 和其他对象数据。对话系统
与脚本运行时因此需要共同推进。

### M3：第一段连续剧情

目标：从启动开始完成一段可重复验证的真实剧情流程。

- [x] 加载队伍、角色属性和全局对象定义
- [x] 支持剧情需要的对象移动、场景修改和队伍变化
- [x] 实现基础菜单以及物品获得、失去和查看
- [x] 播放场景 BGM 和关键 VOC 音效
- [x] 持久化已访问场景的事件对象和场景进入脚本入口
- [x] 持久化金钱及其余额不足条件分支
- [x] 持久化当前剧情流程所需的全局状态
- [x] 提供运行期开发状态快照

验收：可以连续完成选定剧情片段；重新进入场景或恢复状态后，已发生的变化不会重置。

### M4：推进剧情到第一场战斗

目标：优先补齐会阻断真实剧情的交互和脚本能力，让自动化流程能够稳定抵达第一场战斗入口。
执行顺序按“剧情是否还能继续”排序：

1. [ ] **背包使用物品**：从物品菜单选择并使用恢复类、剧情类和消耗类物品，正确处理目标、效果、数量扣除和不可使用条件
2. [ ] **剧情阻塞 opcode**：按真实流程逐条补齐物品使用、条件分支、对象状态、队伍变化、场景进入/传送和过场所需脚本指令
3. [ ] **装备与法术的剧情前置**：支持装备更换及属性刷新、习得和场景中使用法术；只实现抵达第一场战斗确实需要的规则
4. [ ] **商店与经济链路**：完善买入、卖出、价格、持有数量和脚本购买条件，让获得物品、花费金钱和剧情分支形成闭环
5. [ ] **连续剧情回归与快照恢复**：串联启动、获得和使用物品、跨场景分支及快照恢复，并把遇到的首个未支持行为作为下一项开发输入

验收：真实资源无窗口检查和手工流程都能从启动稳定推进到第一场战斗入口；途中不需要跳过脚本、
手工修改状态或使用调试传送。

### M5：第一次完整战斗

目标：完成“真实剧情触发战斗 -> 战斗结算 -> 返回场景”的最小闭环。

- [ ] 从场景脚本创建战斗状态并加载敌我双方和基础属性
- [ ] 实现最小指令选择、普通攻击、伤害和死亡判定
- [ ] 实现胜负、经验、角色成长和物品结算
- [ ] 添加必要的战斗 UI、输入、动画、音效和脚本钩子
- [ ] 结算后恢复场景状态并继续后续剧情脚本
- [ ] 为伤害、死亡、奖励和状态变化增加不依赖窗口的规则测试

验收：从 M4 的连续剧情流程进入一场真实数据驱动的战斗，能够结束、结算、返回场景并继续剧情。

### M6：兼容性扩展

目标：在剧情和首场战斗闭环上逐项扩大原版内容覆盖面。

1. [ ] **扩展跨场景剧情覆盖**：继续按真实流程补充脚本 opcode、物品、装备、法术、商店和角色成长规则
2. [ ] **扩展战斗系统**：补充战斗指令、状态、毒、敌人行为和特效，扩大真实敌人和战斗脚本覆盖
3. [ ] **完善原版表现**：实现对话逐字显示、剩余文本控制符、调色板动画和过场/RNG 动画
4. [ ] **完善音频兼容**：补充 MIDI/VOC 的循环、通道、音量控制和更多资源变体
5. [ ] **存档兼容与长流程回归**：支持原版存档读取，并增加多片段串行测试和更长剧情覆盖

M6 仍按可验证的剧情片段持续迭代，不等待所有系统一次性完成；表现和兼容性工作不得阻塞新的
剧情回归基线。

## 持续工作轨道

以下工作贯穿所有里程碑，不单独作为阻塞后续开发的线性阶段：

| 轨道 | 工作方式 |
|---|---|
| 格式研究 | 研究当前里程碑需要的数据格式，并同步到 `docs/formats/` |
| 核心模型 | 保持世界更新确定、平台无关，并为规则增加内存 fixture 测试 |
| 平台适配 | 提供时间、输入、窗口和音频后端，不把业务规则放入事件循环 |
| 表现层 | 按可玩片段增加地图、角色、UI、动画和音效能力 |
| 验证 | 同时维护单元测试、真实资源检查和阶段性手工 smoke test |

新功能应尽量服务于当前里程碑的端到端闭环。格式解析或系统抽象只有在真实内容需要时
才扩展，避免提前实现彼此尚未连接的大型子系统。

## 构建与运行

需要 Rust 工具链以及用户自行提供的正版游戏数据。将至少以下文件放入 workspace
根目录的 `data/`：

```text
PAT.MKF
MAP.MKF
GOP.MKF
MGO.MKF
RGM.MKF
DATA.MKF
SSS.MKF
VOC.MKF
MIDI.MKF
TimGM6mb.sf2
WORD.DAT
M.MSG
WOR16.ASC
WOR16.FON
```

背景音乐还需要一个 General MIDI SoundFont，默认文件名为 `data/TimGM6mb.sf2`。该文件
可以从 Debian 的 `timgm6mb-soundfont` 包获得；它和原版游戏资源一样保留在本地
`data/`，不会提交到仓库。也可以将其他兼容 GM 的 SF2 文件重命名为该文件名。

构建并打开当前场景查看器：

```shell
cargo build
cargo run -p pal-launcher
```

运行时按 `F3` 切换碰撞调试，红色菱形为阻挡 tile，绿色菱形为可通行 tile，黄色十字
为玩家实际参与碰撞检测的逻辑坐标；按 `F4` 切换事件对象调试，所有对象显示小十字，
橙色表示触发脚本、青色表示自动脚本、品红色表示两者兼有，灰色表示无脚本或隐藏状态，
当前脚本对象显示白色 `#ID`；按 `F6` 切换右上角脚本 inspector。脚本 inspector 显示
场景、玩家、脚本 owner、触发类型、entry、opcode、三个参数、调用深度和等待帧，以及当前
对象的位置、状态、层级、触发模式、sprite、动画帧、方向、可见性和阻挡能力，脚本
结束后保留最近一条指令便于检查。`0xffff` 的系统脚本显示为 `SYSTEM`，不会映射成场景对象。

探索时按 `Esc` 或 `Backspace` 打开物品菜单，使用上下方向键选择物品，按确认键使用
可用物品；单体物品会继续选择队员，灰色物品当前不可在场景中使用。取消键返回上一层或
关闭菜单。

没有运行剧情脚本或显示对话时，按 `F5` 捕获运行期开发状态快照，按 `F9` 恢复。
快照包含玩家、队伍、物品、音乐和已访问场景状态，并通过临时文件写入 workspace 根目录的
`rust-pal.snapshot.json`。该开发格式带版本号，不承诺与最终原版兼容存档格式一致。

执行不打开窗口的真实资源检查：

```shell
cargo run -p pal-launcher -- --check-assets
```

完整开发检查：

```shell
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

`data/` 和 `reference/` 均被忽略，不应提交其中的版权资源或参考实现副本。

## 目录结构

```text
rust-pal/
├── pal-assets/       # MKF、palette、RLE、sprite、YJ_1 等资源解析
├── pal-core/         # 平台无关的地图、角色和后续游戏状态
├── pal-desktop/      # winit 窗口、pixels framebuffer 和桌面适配
├── pal-launcher/     # 桌面程序入口与装配
├── docs/formats/     # 已研究的数据格式文档
├── data/             # 本地原版游戏资源，不纳入版本控制
└── reference/        # 本地参考实现，不纳入版本控制
```

## 技术选择

- `winit`：跨平台窗口与事件循环
- `pixels`：呈现固定 `320x200` RGBA framebuffer
- `rustysynth`：使用 `data/TimGM6mb.sf2` 对标准 MIDI 进行完整 SoundFont 合成
- `rodio`：输出合成后的 `44100 Hz` 立体声 PCM 和 VOC 音效
- 纯 Rust YJ_1：避免依赖预编译对象或 C FFI，并对不可信输入执行边界检查
